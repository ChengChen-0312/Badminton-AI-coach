--------------------------------
PROJECT OVERVIEW
--------------------------------
Badminton-AI-coach is a computer-vision-first badminton analysis pipeline. Given a match video, it detects the court plane, tracks players and the shuttle, estimates a court homography (image → real court coordinates), and infers structured “stroke” events (e.g., contact/landing frames, hitter side/role, regions). It produces shareable outputs (Markdown/JSON/CSV + heatmaps/timelines).

The repo also includes an optional “AI score” layer that uses local MLX models (teacher/student, optional LoRA adapters) to score strokes and generate feedback, plus scripts to distill teacher labels into a student dataset.

--------------------------------
HIGH-LEVEL PIPELINE
--------------------------------
Entry (scripts) →
1) `src/pipeline/analyse_video.py`: per-frame vision (ball/player detection + tracking), court detection, homography estimation
2) `src/pipeline/extract_strokes.py`: temporal/spatial reasoning to extract stroke events + regions (contact/landing/hitter)
3) `src/pipeline/report_generator.py`: aggregate results → Markdown/JSON/CSV + `src/analysis/*` figures (heatmaps/timeline/stats)
4) Optional: `src/ai_score/*` teacher/student MLX scoring + distillation tooling in `scripts/*`

--------------------------------
KEY INVARIANTS & DESIGN RULES
--------------------------------
- Court corner order is always `LB, RB, RT, LT` (manual calibration + homography + detector output must agree).
- Canonical court coordinates are in meters; `y=0` corresponds to the near baseline (bottom), increasing towards far baseline.
- Pose is optional: pipeline should still run without MediaPipe (pose features become `null`).
- Court detection has a hard “reject” path; downstream homography/heatmaps assume corners are valid.

--------------------------------
CURRENT COMPLEXITY PAIN POINTS
--------------------------------
- Court detection is heuristic-heavy (mask thresholds, morphology, candidate generation + scoring) and sensitive to lighting/occlusion.
- Multiple optional runtime stacks (ultralytics/YOLO, mediapipe, MLX teacher/student) increase environment variability.
- Some modules appear stale/broken:
  - `src/spatial_logic/region_logic.py` imports a missing symbol (`zone_from_real_court_pos`) from `src/geometry/region_definitions.py`.
  - `src/pipeline/action_feedback_pipeline.py` appears mismatched with current `ActionFeedback` constructor/modes.

--------------------------------
SUGGESTED NEXT IMPROVEMENTS (HIGH LEVEL)
--------------------------------
- Add a small evaluation harness (manifest + batch runner) to measure court-detection success/failure reasons and tune thresholds safely.
- Consolidate/validate configuration paths (court corners, model paths) and expose a single “runtime config” object for scripts.
- Stabilize public APIs between modules (e.g., `ActionFeedback` construction, region labeling helpers) to reduce breakages.
- Keep court detection modular: introduce a line-segment candidate generator (FAST/ROBUST stages) as an additional candidate source before CC/hull fallback, reusing existing `_validate_and_score()` and debug metrics.

COURT DEBUG FLOW (10 lines max)
- `scripts/demo_friend.py` loads video/config, then calls `src/pipeline/analyse_video.py`.
- `analyse_video` runs detection/tracking and invokes `CourtDetector.detect_court()` (auto) or uses calibrated `vision.court_corners` (manual).
- `CourtDetector.detect_court()` returns corners in `LB, RB, RT, LT` order or sets `analysis.court_detection` to `auto_failed` with `reason/confidence`.
- If corners exist, homography is computed (`src/geometry/homography`) and used to map image points to real-court coordinates.
- When auto court detection fails, downstream court-mapped outputs are gated/disabled (heatmaps/regions depend on valid homography).
- `scripts/demo_friend.py` selects a debug frame (`--court-debug-frame` → `analysis.court_detection.frame_idx` → 0) and writes `court_detect_debug.jpg` using `analysis.court_detection` fields (`source/method/edge_support/metrics`).

FOUNDATIONS
--------------------------------
- Frame IO: `cv2.VideoCapture` reads BGR frames in `src/pipeline/analyse_video.analyse_video`; conversion to RGB via `cv2.cvtColor(..., BGR2RGB)` before calling RGB-expecting vision modules (e.g., `CourtDetector.detect_court()`).
- Frame sampling: `src/data/frame_cache.extract_frames()` provides random-access uniform sampling via `CAP_PROP_POS_FRAMES` and returns stacked RGB frames.
- Court keyframe choice: `analyse_video` samples early frames (`vision.court_detect_samples` × `vision.court_detect_stride`) and keeps the highest `CourtDetector.last_confidence`; chosen `frame_idx` is stored in `analysis.court_detection`.
- Optional deps gating: pose is enabled by config and guarded by a try/except around `PoseEstimator()` init; YOLO-based detectors are instantiated in pipeline (`PlayerDetector`, `BallDetector`) and may raise on missing deps. [VERIFY exact ImportError behavior]
- Runtime config: scripts load YAML into a dict and pass it into the pipeline; manual court corners are accepted via `vision.court_corners` in `LB, RB, RT, LT` order.
